# 产线布局 PDF → 工位投影面积 → 公摊工时 / 装柜数量 / 国际运费

从 AutoCAD 导出的产线布局 PDF 中，自动计算**每个工位的实际占地（投影）面积**，相加得到产线精细面积；
同时保留原来的**"产线总长 × 总宽"**粗算作为基准对比。面积结果用于：

1. **厂内公摊工时**：面积 × 公摊工时系数（现行 0.52 h/m²）；
2. **集装箱数量**：面积 × 包装系数 ÷（40HQ 地板面积 × 利用率）；
3. **国际运费**：箱数 × 单箱费用（海运价 + 杂费）。

> 方法是通用的：所有阈值都在 `config.yaml`，代码中没有任何针对某张图纸的坐标或颜色。
> 新增一张图纸，只需在配置里写 **PDF 路径 + 图上标注的总尺寸**。

```bash

| 文件 | 内容 |
|---|---|

```

| 功能 | 说明 |
|---|---|
| 上传 | 一次 1–10 张 PDF；名称、标注总尺寸、比例（mm/点）均可选填 |
| 结果 | 精细面积、基准面积、公摊工时、40HQ 箱数、运费；每张图的叠加图、线体基准、工位明细 |
| Excel | 与命令行生成的工作簿相同（全部为公式）；可在网页修改业务参数后重新生成，不重新测量面积 |
| 图纸库 | 上传过的 PDF 按**内容 SHA-256** 识别（改名也能识别）。同一文件 + 同样的标注尺寸 + 同样的提取参数与测量代码 → 直接复用上次的测量结果；文件内容有任何改动都会重新测量 |
| 标注总尺寸 | 可留空：同一文件沿用上次填写的值；从未填写过时，任务会停下来，标出用来定比例尺的那条线，请用户填写后继续（无需重新上传） |
| OCR | 未安装 Tesseract 时自动跳过工位识别：只给整图投影面积（精细面积取整图面积），并在界面与工作簿中注明 |

> 比例尺只能来自图上的标注数字。程序不猜测比例尺；同一文件填写一次后会被记住。
> 以后可在装有 Tesseract 的服务器上用 OCR 读出尺寸数字，并与第二个方向的尺寸交叉核对后再自动采用。

## 算法步骤

### 第 1 步　读取矢量
用 PyMuPDF 读出 PDF 中每条线段、矩形、曲线及其**颜色**和**绘制类型**。
CAD 打印时，**文字被转成"填充+描边"路径，设备轮廓是纯描边路径**，据此把文字与设备彻底分开。

### 第 2 步　比例尺（自动）
图上最长的"线状"路径 = 标注总尺寸线。
`比例 (mm/点) = 标注值 ÷ 该线长度`
本例：101 图 75000 mm ÷ 1176.2 点 = **63.76 mm/点**；102 图 115000 ÷ 1131.6 = **101.63 mm/点**（与 22000 mm 宽度交叉验证一致）。
如识别失败，可在配置中直接写 `mm_per_pt`。

### 第 3 步　识别非设备区域
| 区域 | 判定规则 | 参数 |
|---|---|---|
| 厂房范围 | 长度 ≥ 60% 总尺寸的线条外包框 | `building.min_line_frac` |
| 墙体/填充带 | 单根 ≥ 1.5 m 的 45° 斜线，成片 ≥ 40 m²（设备内部斜线都很短） | `hatch.*` |
| 线体 | 沿产线方向贯通 ≥ 80% 的填充带把厂房分隔成若干线体 | `lane_separator_frac` |

### 第 4 步　去掉非设备线条
| 内容 | 规则 | 参数 |
|---|---|---|
| 文字（标签、图名、水印） | 填充+描边类型路径 | — |
| 安全围栏、注释 | 黄色 | `exclude_colors` |
| 墙线、轴线、尺寸线 | 单条路径 > 14 m | `max_path_extent_mm` |
| 物流通道/AGV 路线 | 灰色直线段 > 4 m | `route_grey_range`, `route_max_segment_mm` |
| AGV 转弯圆 | OpenCV 霍夫圆检测（半径 0.6–1.3 m）后擦除 | `agv_circles.*` |

### 第 5 步　计算投影面积
1. 剩余设备线条栅格化（约 16–25 mm/像素）；
2. 闭合 < 150 mm 的缝隙（同一设备的线条连成整体）；`gap_close_mm`
3. 填充 **< 20 m²** 的封闭区域 = 设备内部；更大的封闭区是通道围合出来的空地，不填；`max_hole_fill_m2`
4. 形态学开运算去掉宽度 < 250 mm 的细线（墙线、虚线、箭头）；`min_feature_mm`
5. 统计像素面积 = **实际投影面积**。

### 第 6 步　识别工位标签（OCR）
1. 黑色文字按 0.8 m 间距聚成标签块；字号 > 3 倍中位数的视为图名，忽略；
2. 每个标签块单独渲染（600 dpi）、转正（竖排文字旋转 90°）、Tesseract OCR，解析 `OP-xx` 编号和名称；
3. **编号纠错**：同一列标签编号应连续，夹在 n−1 与 n+1 之间读错的改为 n；读不出编号的按相邻步长外推（工作簿中标"推断"）；
4. **名称修正**：OCR 难免有错字，在配置 `station_overrides` 中人工修正（只需修正一次）。

### 第 7 步　面积按工位分摊
- 横向：每块设备面积归属**横向距离最近的标签列**（产线两侧各有一列标签）；
- 纵向：同一列相邻两个标签的**中点为工位分界**；
- 各工位面积相加 = 精细面积（与第 5 步总面积一致，可校验）。

### 第 8 步　基准（保留原粗算）
每条线体取设备外包矩形 **总长 × 总宽**，多条线体相加（不含线体之间的通道）。

### 第 9 步　公摊工时、装柜、运费（工作簿中为公式）
```
公摊工时        = 面积 × 公摊工时系数(0.52 h/m²)          —— 基准、精细两种口径并列
包装后面积      = 精细面积 × 包装系数(1.15)
40HQ 箱数(中)   = ROUNDUP( 包装后面积 ÷ (12.03 × 2.35 × 平均利用率) )
箱数(低/高)     = 面积 × 误差系数(0.85/1.10) × 包装系数 ÷ (地板面积 × 利用率 75%/55%)
框架箱数        = 箱数 × 超限比例(10%)
运费            = 普通箱数 × (海运价 + 杂费) + 框架箱数 × (海运价 × 2.0 + 杂费)
```

## 本例结果（101、102 两张图）

| | 101 Power Module Line | 102 CTP Line |
|---|---|---|
| 识别工位 | 11 / 11 | 35 / 35 |
| ① 基准：总长×宽 | 69.8×6.9 ≈ **482 m²** | 103.3×20.2 + 107.2×20.4 ≈ **4,274 m²** |
| ② 精细：工位面积之和 | **216 m²** | **1,519 m²** |
| 精细 / 基准 | 45% | 36% |
| 公摊工时（0.52 h/m²）基准 → 精细 | 250 → **112 h** | 2,222 → **790 h** |
| 40HQ 箱数（中 / 范围） | 14（10–18） | 96（71–124） |
| 运费 上海→鹿特丹（中） | ≈ US$ 81k | ≈ US$ 568k |

## 精度与局限

- **面积**：约 −15% / +10%。浅灰色设备可能填充不全；少量线条噪声。用叠加图人工核对。
- **工位分界**：按相邻标签中点划分，跨两个工位的长设备（如输送线）会被切分，边界处有少量互相归属。
- **OCR**：编号经连续性校验后本例 100% 正确；名称约 1/3 有错字，需在配置中修正一次。
- **PDF 中没有**设备高度和重量 → 是否需要框架箱/开顶箱、是否超重，需补充设备总图或清单。
- 箱数和运费参数（包装系数、利用率、杂费）为行业经验值，**应以历史装柜记录校准**。

## 新增一张图纸

```yaml
drawings:
  - id: "103"
    name: "新产线名称"
    pdf: "drawings/103-xxx.pdf"
    reference_length_mm: 90000      # 图上最长尺寸线的标注值
```
运行两步命令 → 打开 `<id>_overlay.png` 和 `<id>_stations.png` 核对 → 如有 OCR 名称错误，加到 `station_overrides` 后重跑。
