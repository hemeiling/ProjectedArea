# 产线布局 PDF → 工位投影面积 → 公摊工时 / 装柜数量 / 国际运费

从 AutoCAD 导出的产线布局 PDF 中，自动计算**每个工位的实际占地（投影）面积**，相加得到产线精细面积；
同时计算**"产线总长 × 总宽"**基准面积（工时表“公摊&投影面积”现行录入的口径）。面积结果用于：

1. **厂内公摊工时**：钳工、电工各算一次 面积 × 系数（现行均为 0.52 h/m²）；面积口径默认用基准（总长×宽），可在参数中改为精细面积；
2. **集装箱数量**：面积 × 包装系数 ÷（40HQ 地板面积 × 利用率）；
3. **国际运费**：箱数 × 单箱费用（海运价 + 杂费）。

> 方法是通用的：所有阈值都在 `config.yaml`，代码中没有任何针对某张图纸的坐标或颜色。
> 新增一张图纸，只需在配置里写 **PDF 路径 + 图上标注的总尺寸**。

> 以后可在装有 Tesseract 的服务器上用 OCR 读出尺寸数字，并与第二个方向的尺寸交叉核对后再自动采用。

## 算法步骤

### 第 1 步　读取矢量
用 PyMuPDF 读出 PDF 中每条线段、矩形、曲线及其**颜色**和**绘制类型**。
CAD 打印时，**文字被转成"填充+描边"路径，设备轮廓是纯描边路径**，据此把文字与设备彻底分开。

### 第 2 步　比例尺（自动）
图上最长的"线状"路径 = 标注总尺寸线。
`比例 (mm/点) = 标注值 ÷ 该线长度`
本例：101 图 75000 mm ÷ 1176.2 点 = **63.76 mm/点**；102 图 115000 ÷ 1131.6 = **101.63 mm/点**（与 22000 mm 宽度交叉验证一致）。
如识别失败，可在配置中直接写 `mm_per_pt`。

### 第 3 步　识别非设备区域
| 区域 | 判定规则 | 参数 |
|---|---|---|
| 厂房范围 | 长度 ≥ 60% 总尺寸的线条外包框 | `building.min_line_frac` |
| 墙体/填充带 | 单根 ≥ 1.5 m 的 45° 斜线，**同一颜色**成片 ≥ 40 m²（设备内部斜线都很短；设备上不同颜色的“方框+对角线”符号不会与填充带连成一片） | `hatch.*` |
| 线体 | 沿产线方向贯通 ≥ 80% 的填充带把厂房分隔成若干线体 | `lane_separator_frac` |

### 第 4 步　去掉非设备线条
| 内容 | 规则 | 参数 |
|---|---|---|
| 文字（标签、图名、水印） | 填充+描边类型路径 | — |
| 安全围栏、注释 | 黄色 | `exclude_colors` |
| 墙线、轴线、尺寸线 | 单条路径 > 14 m | `max_path_extent_mm` |
| 物流通道/AGV 路线 | 灰色直线段 > 4 m | `route_grey_range`, `route_max_segment_mm` |
| AGV 转弯圆 | OpenCV 霍夫圆检测（半径 0.6–1.3 m）后擦除 | `agv_circles.*` |

### 第 5 步　计算投影面积
1. 剩余设备线条栅格化（约 16–25 mm/像素）；
2. 闭合 < 150 mm 的缝隙（同一设备的线条连成整体）；`gap_close_mm`
3. 填充 **< 20 m²** 的封闭区域 = 设备内部；更大的封闭区是通道围合出来的空地，不填；`max_hole_fill_m2`
4. 形态学开运算去掉宽度 < 250 mm 的细线（墙线、虚线、箭头）；`min_feature_mm`
5. 统计像素面积 = **实际投影面积**。

### 第 6 步　识别工位标签（OCR）
1. 黑色文字按 0.8 m 间距聚成标签块；字号 > 3 倍中位数的视为图名，忽略；
2. 每个标签块单独渲染（600 dpi）、转正（竖排文字旋转 90°）、Tesseract OCR，解析 `OP-xx` 编号和名称；
3. **编号纠错**：同一列标签编号应连续，夹在 n−1 与 n+1 之间读错的改为 n；读不出编号的按相邻步长外推（工作簿中标"推断"）；
4. **名称修正**：OCR 难免有错字，在配置 `station_overrides` 中人工修正（只需修正一次）。

### 第 7 步　面积按工位分摊
- 横向：每块设备面积归属**横向距离最近的标签列**（产线两侧各有一列标签）；
- 纵向：同一列相邻两个标签的**中点为工位分界**；
- 各工位面积相加 = 精细面积（与第 5 步总面积一致，可校验）。

### 第 8 步　基准（工时表现行口径）
每条线体取设备外包矩形 **总长 × 总宽**，多条线体相加（不含线体之间的通道）。

### 第 9 步　公摊工时、装柜、运费（工作簿中为公式）
```
公摊工时        = 所选口径面积 × 钳工系数(0.52) + 所选口径面积 × 电工系数(0.52)
                  —— 口径默认基准（总长×宽），可选精细；两种口径的工时并列显示
包装后面积      = 精细面积 × 包装系数(1.15)
40HQ 箱数(中)   = ROUNDUP( 包装后面积 ÷ (12.03 × 2.35 × 平均利用率) )
箱数(低/高)     = 面积 × 误差系数(0.85/1.10) × 包装系数 ÷ (地板面积 × 利用率 75%/55%)
框架箱数        = 箱数 × 超限比例(10%)
运费            = 普通箱数 × (海运价 + 杂费) + 框架箱数 × (海运价 × 2.0 + 杂费)
```

## 精度与局限

- **面积**：约 −15% / +10%。浅灰色设备可能填充不全；少量线条噪声。用叠加图人工核对。
- **填充带**：按颜色判定。设备上的斜线符号如果与通道填充带**同色**且相距 < 3 m，仍会被并入填充带而漏算（2026-11 起按颜色区分，101 图 OP-01 两台提升机由此从漏算改为计入：215.9 → 225.1 m²）。
- **工位分界**：按相邻标签中点划分，跨两个工位的长设备（如输送线）会被切分，边界处有少量互相归属。
- **OCR**：编号经连续性校验后本例 100% 正确；名称约 1/3 有错字，需在配置中修正一次。
- **PDF 中没有**设备高度和重量 → 是否需要框架箱/开顶箱、是否超重，需补充设备总图或清单。
- 箱数和运费参数（包装系数、利用率、杂费）为行业经验值，**应以历史装柜记录校准**。

## DXF 输入（按图块计算，`dxf_footprint.py`）

有 DXF（或由 DWG 另存的 DXF）时，直接读 CAD：单位来自文件，不需要“标注总尺寸”；每台设备是一个图块，
面积来自设备轮廓多边形，不受 PDF 线条颜色和像素边缘的影响。与 PDF 方法同一面积口径、同一组形态学参数。

```bash
python dxf_footprint.py config.yaml --out results_dxf        # 配置中带 dxf: 的图纸
```

| 步骤 | 规则 |
|---|---|
| 单位 | `$INSUNITS`；未声明（0）时必须在配置写 `dxf_unit_mm` 和依据，否则不出面积 |
| 设备 | 模型空间的每个图块插入：在图块自身坐标里求一次外轮廓（曲线离散 1 mm、10 mm/像素栅格、闭合 < 150 mm 缺口、填充 < 20 m² 的内部、去掉 < 250 mm 的细线），再按插入的平移/旋转/镜像/缩放/拉伸方向放到图上；同一图块只算一次 |
| 打散的设备 | 不在图块里的线条按 2 m 邻接聚团，每团同样求外轮廓 |
| 合计 | 所有设备轮廓取并集：重叠只算一次，设备之间的空地不填 |
| 基准（总长×宽） | 按线体分开：与产线长边平行、贯穿全图、宽 ≥ 3 m（`lane_gap_mm`）的空走道 = 线体之间的分隔；每条线体取 ≥ 2 m² 设备块的外包矩形，再相加（线体之间的走道不计入）。更窄的贯通空隙是线体内的操作通道，不分开。4 张样例图中单线体图（101、103）横向没有任何空隙，双线体图（102、104）各只有一条 9.5–9.7 m 的走道 |
| 不计入 | 文字/标注/引线；关闭、冻结、不打印图层和 Defpoints；黄色（ACI 2）；绑定外部参照图层（名称含 `$0$`，建筑底图）；单根 > 14 m 的线；背景框（框住大部分图块、内部基本是空的）；产线范围以外的图形 |
| 单列（不进主结果） | **移动设备**（AGV、随行小车、托盘）、**待定**（只有外框、没有内部细节的图形；人工标为待确认的符号） |
| 人工分类 | `config.yaml` 中按图块名写 `overrides`，并写该文件的 `sha256`：文件一改，分类即失效，不会套到新版本 |
| 核对 | 每个插入的类别与原因、`<id>_overlay.png`（绿 = 计入，青色框 = 各线体外包，红 = 排除，紫 = 移动，橙 = 待定，蓝 = 产线范围）、`<id>_footprint.wkt`（计入的轮廓）；自检：每个轮廓必须落在 ezdxf 独立算出的图块范围内（检查旋转、镜像） |

**101：DXF 与 PDF 逐像素对比**（同一产线，配准后 IoU 0.89）：DXF 计入的部分 PDF 也都计入（DXF 独有仅 1.1 m²）；
PDF 多出的 23.5 m² 中，8.5 m² 是 PDF 像素边缘造成的外扩（轮廓外 ≤ 32 mm），其余是 PDF 填进去的设备之间的空地、
人员符号、尺寸数字，以及 DXF 单列为待定的符号与小车。DXF 的结果更符合“设备外轮廓并集、不含空地”的定义。

**局限**：读大文件慢、占内存（见上表，主要是 ezdxf 整体读入）；**门的开启弧线（扇形）和机器人工作半径圆会被当作封闭区域填充计入**（104 图明显，与 PDF 方法相同；其中也可能有真正的转台），需要专门识别；线体按贯通走道划分，外包矩形与坐标轴平行（斜放的产线外包会偏大）；102 两个车间顶部各有一条 22 × 0.92 m、以散线画在模型空间的长条（约 20 m²/条）被计入设备，线体宽度（22.4 / 22.0 m，PDF 方法为 20.2 / 20.4 m）和上边都由它们决定；不计它们时线体 1 长 103.2 m（PDF 方法 103.3 m）、投影面积少 40.5 m²。它们是设备还是建筑构件待确认，而散线团目前不能按图块名人工分类；工位划分（OCR）尚未接入 DXF；
设备框架内围出的地面（如测试房、围栏内）与 PDF 方法一样被填充，是框架还是围栏需按图确认。
网页版/桌面版可直接上传 DXF（见上文“网页版”）；内存峰值约为文件大小的 7–25 倍，大文件请在内存充足的电脑上用桌面版或本机网页版。

## 长期建议
让设计部门同时导出 **DXF**：每台设备是独立图块（Block），带名称和图层，可直接精确到单台设备的面积，无需图像识别和 OCR。
